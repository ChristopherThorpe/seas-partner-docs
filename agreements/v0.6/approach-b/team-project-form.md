## 1. Choices and defaults

If a choice is left blank, or more than one box is checked (other than MIT and Apache together), the default applies. An FSL license checked for an individual project is treated as blank. The choices apply to every Project Student.

## 2. Ownership and licenses

The Project Students own their Project Work Product, subject to Harvard's rights (Course Rules Section 6.2). Each Project Student licenses their rights in it to everyone who receives a copy, under the licenses checked in boxes A and B. If MIT and Apache are both checked, each recipient chooses between them. "None" means no public license for that category, and "Other" means the license named. On a team, the teammates' licenses and the buyout in Course Rules Section 5 apply as that section provides.

## 3. FSL

If an FSL license is checked:

(a) The Project Students own the Project Software jointly. To the extent that it is not already a joint work, each assigns to each other an undivided interest in their rights in it.

(b) They together license the Project Software under the checked FSL license.

(c) Each Project Student may use the Project Software for any purpose, including commercially, whether personally or through a Student Company. None of these uses is a competing use under the FSL license, and no one may claim otherwise.

(d) No one may license or distribute the Project Software except under the checked FSL license, or to a Student Company under (c), unless the choices are changed under Section 6.

(e) No Project Student owes another an accounting of profits.

(f) A majority of the Project Students may, by written notice to all of them, name or replace one Project Student or one Student Company as the "**FSL Representative**". The FSL Representative manages releases of the Project Software and any enforcement of the FSL license for all of them.

(g) Each released copy carries a notice reading "Copyright", followed by the year of first release and the full names of the Project Students. A Project Student may assign their interest to a Student Company and name it in the notice instead, if the company first agrees in writing to be bound by this form.

## 4. Information

If box C is Course Private, everything that the Project Students share about the Project with the Course Staff and classmates is Course Private Information. Everyone in the Course must then keep it within the Course Community under Course Rules Section 2.2. A Project Student may make it public only with every Project Student's written consent. If box C is Open, information about the Project is not restricted. Either way, the Course Rules bind every Project Student.

## 5. Instructor approval

An individual project, and any choice other than Open Science, needs the Course instructor's approval in writing (email is enough). By signing, the Project Students certify that approval, as shown in box D. The instructor does not sign.

## 6. Changes, joining, and enforcement

The choices change only in a writing signed by every Project Student then taking part, who certify any approval that Section 5 requires. A change does not affect a former Project Student's earlier contributions unless they sign it. A student who joins later signs below and is bound as of the date the first Project Student signed. Project Students may enforce this form against each other.
